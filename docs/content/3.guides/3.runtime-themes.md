---
title: Runtime Themes
description: Switch already shipped theme values at runtime through CSS variables and Nuxt UI app config.
---

Runtime themes are optional. A normal brand layer exposes one primary `id.theme`; add `id.themes[]` only when the active app intentionally ships a picker, preview mode, tenant preview, or editor workflow.

Every shipped theme should include both `light` and `dark` CSS variables, because Nuxt UI applications commonly expose color-mode switching through `useColorMode()`.

The `id` documentation uses this pattern itself. Its default theme is the standard Nuxt UI baseline, and the optional `happydesigns` runtime theme is imported from `themes/happydesigns` as a local demonstration of the contract shape. Canonical happydesigns doctrine remains in `@happydesigns/brand`.

`IdThemeSelect` keeps the selected runtime theme in scoped Nuxt state and persists it in a scoped Nuxt cookie based on the current `id.name`, so a docs preview, tenant preview, or editor preview keeps the same theme after reload without affecting other apps. Use `createBrandThemeStateKey(id.name)` and `createBrandThemeCookieName(id.name)` when external code needs to inspect or clear the same runtime selection.

```ts [app.config.ts]
import { defineBrandTheme } from '@happydesigns/id'

const clientTheme = defineBrandTheme({
  name: 'client',
  label: 'Client',
  cssVariables: {
    light: {
      '--ui-bg': 'white',
      '--ui-text': '#334155',
      '--ui-text-highlighted': '#020617'
    },
    dark: {
      '--ui-bg': '#020617',
      '--ui-text': '#E2E8F0',
      '--ui-text-highlighted': 'white'
    }
  },
  ui: {
    colors: {
      primary: 'blue',
      neutral: 'slate'
    },
    button: {
      slots: {
        base: 'rounded-md font-medium'
      },
      defaultVariants: {
        color: 'primary',
        variant: 'solid',
        size: 'md'
      }
    },
    card: {
      slots: {
        root: 'rounded-lg shadow-none'
      }
    }
  }
})

const previewTheme = defineBrandTheme({
  ...clientTheme,
  name: 'client-preview',
  label: 'Client Preview',
  ui: {
    ...clientTheme.ui,
    colors: {
      ...clientTheme.ui.colors,
      primary: 'emerald',
      neutral: 'zinc'
    }
  }
})

export default defineAppConfig({
  id: {
    name: clientTheme.name,
    theme: clientTheme,
    themes: [previewTheme]
  }
})
```

## Switching

`useBrandTheme()` returns the primary `id.theme` first, then any additional `id.themes[]` entries that are not duplicates.

```vue [ThemeToggle.vue]
<script setup lang="ts">
const {
  themes,
  selectedName,
  setTheme
} = useBrandTheme()

const selectedTheme = computed({
  get: () => selectedName.value,
  set: value => setTheme(value)
})
</script>

<template>
  <USelect
    v-model="selectedTheme"
    :items="
      themes.map(theme => ({
        label: theme.label,
        value: theme.name
      }))
    "
    value-key="value"
    label-key="label"
  />
</template>
```

## Color mode

Use Nuxt's standard color-mode composable. `id` watches the document color-mode class and reapplies the selected theme's matching light or dark variables.

```vue [ColorModeButton.vue]
<script setup lang="ts">
const colorMode = useColorMode()
const isDark = computed(() => colorMode.value === 'dark')
</script>

<template>
  <UButton
    color="neutral"
    variant="ghost"
    :icon="isDark ? 'i-lucide-sun' : 'i-lucide-moon'"
    square
    @click="colorMode.preference = isDark ? 'light' : 'dark'"
  />
</template>
```

## Runtime-safe values

Use runtime themes for:

- CSS variables
- typography variables
- Nuxt UI semantic colors in `ui.colors`
- component slots and default variants that use shipped classes

Do not use runtime themes for:

- unbundled Vue components
- arbitrary remote CSS
- uncompiled Tailwind class names
- domain behavior
- credentials
