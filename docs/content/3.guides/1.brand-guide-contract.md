---
title: Brand Guide Contract
description: Define brand guides with typed metadata, palettes, tokens, assets, voice, component coverage, and usage rules.
---

Use `defineBrand` for the neutral source object, then expose optional public guide metadata with `defineBrandGuide`. Keep durable guide content in normal typed arrays. Guide prose and coverage do not need to ship with every app that consumes the brand.

```ts [brand.ts]
import {
  createBrandGuideAssets,
  defineBrandGuide,
  defineBrand,
  type BrandGuideContent
} from '@happydesigns/id'

export const brandIdentity = defineBrand({
  name: 'client-brand',
  packageName: '@client/brand',
  claim: 'The reusable identity guide for Client Brand.',
  logoAssetPaths: {
    crest: '/brand/crest.svg'
  },
  colors: {
    brand: { 500: '#2563EB' },
    slate: { 500: '#64748B' }
  }
})

export const guideContent = {
  brand: brandIdentity,
  assets: [
    {
      name: 'Client crest',
      role: 'crest',
      path: brandIdentity.logoAssetPaths.crest,
      usage: 'Primary institutional mark.',
      alt: 'Client Brand crest'
    }
  ],
  principles: [],
  sections: [],
  colors: [],
  fonts: [],
  components: [],
  voice: {
    attributes: ['Clear'],
    dos: ['Name the action.'],
    donts: ['Do not obscure the task.'],
    examples: [
      {
        label: 'Button',
        text: 'Save changes'
      }
    ]
  }
} satisfies BrandGuideContent<typeof brandIdentity>

export const brandGuide = defineBrandGuide({
  name: brandIdentity.name,
  packageName: brandIdentity.packageName,
  title: 'Client Brand',
  description: brandIdentity.claim,
  palette: brandIdentity.colors,
  usage: {
    useFor: ['Nuxt UI apps', 'Docus docs'],
    avoid: ['domain behavior', 'authorization']
  },
  voice: guideContent.voice,
  assets: createBrandGuideAssets(guideContent.assets)
})
```

## Recommended sections

For richer guide navigation, keep section metadata in the brand source file and map it into the public guide contract.

```ts [brand-sections.ts]
import { createGuideDocsSections, defineGuideSections } from '@happydesigns/id'

export const sections = defineGuideSections([
  {
    slug: 'colors',
    title: 'Colors',
    description: 'Palette, semantic roles, and usage guidance.',
    icon: 'i-lucide-palette',
    anchors: ['Palette', 'Semantic roles', 'Usage rules']
  }
])

export const docs = {
  sections: createGuideDocsSections(sections)
}
```

## Assets

`assets.logos` is a role map, not a fixed logo model. Use common roles like `logo`, `wordmark`, `wordmarkInverse`, `symbol`, `symbolInverse`, `mark`, or `appIcon` when they fit the brand, but custom roles such as `crest`, `seal`, `signature`, or `partner-lockup` are equally valid.

`BrandGuideAssetEntry` supports `name`, `role`, `path`, `usage`, optional `alt`, and optional `media` (`light`, `dark`, or `any`). `createBrandGuideAssets()` converts those durable guide entries into both `id.guide.assets.logos` and `assets.files`, so documentation, selectors, and components read the same asset source.

The shipped `IdLogo` component can render any configured role through `role="crest"`. If a brand needs richer logic, such as responsive lockups or complex light/dark switching, the brand layer should provide its own logo component.

## Validation

The helpers validate identity and guide data immediately. Invalid names, empty required strings, and malformed URLs fail at the boundary.

Use this failure early. A brand guide should be predictable before it becomes a layer.
