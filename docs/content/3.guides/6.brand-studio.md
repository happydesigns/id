---
title: Brand Studio
description: Create, compare and edit Nuxt UI brands from a versioned source document.
---

[Open Brand Studio](/studio) to start a neutral brand or open an existing `brand.studio.json` document. Studio is an optional Nuxt UI authoring surface, separate from the runtime layer.

## Add Studio to a guide

Extend `@happydesigns/id/studio` in the guide or playground application that already uses the identity runtime. The layer adds `/studio` and `/studio/preview`, plus the shared Components, Landing and Docs scenes. Production applications continue extending only their brand layer.

```ts [app.config.ts]
import document from '../brand.studio.json'

export default defineAppConfig({
  idStudio: { document, sourcePath: 'brand.studio.json', home: '/' }
})
```

Use `/studio?browse=true` for a read-only entry and `/studio?browse=true&view=landing` to open a template. The visitor can explicitly enter customization. Changes are drafts in that browser, never writes to your repository.

## Create or customize

Start with New brand, import a document, or customize the host brand. Identity, color mappings, individual palette stops, fonts and selected component defaults are editable. Compare renders the original and draft in separate frames with the same scene, mode and validation state. On small screens the frames stack. Undo, redo and reset use the loaded document as the baseline.

Named colors, other typography roles, assets, custom component overrides and additional JSON metadata survive round trips. Font controls select stacks available in the project; they do not fetch fonts. Existing component classes may override global controls. Unknown class strings must be compiled in the consuming application before the preview can promise their appearance.

Logo uploads accept PNG, JPEG and WebP. Existing local public assets can remain SVG. Imported documents are JSON data; Studio does not evaluate TypeScript, fetch external assets, or run imported code.

## Review and export

Review & export shows the complete source, a field-level change list and the generated CSS. Download source replaces the configured source file only after the author applies it. Download new project creates a ZIP containing a runtime brand layer, the source, available public assets and a Studio playground. It does not copy custom Vue components or app layouts.

The generated project's Nuxt configuration regenerates CSS from the source. Until `@happydesigns/id` is published, use a reviewed local package or tarball. Install dependencies, then run `pnpm dev` or `pnpm build` in the exported project. Font loading remains the consumer's responsibility.

Studio stores a recoverable draft under a per-brand browser key. Storage failures are surfaced, and replacing unsaved work requires an explicit choice. Export before leaving when storage is unavailable.

## Scope

Nuxt UI is the supported design system. The small CSS generator and historical adapter helpers remain compatible utilities, not a promise of additional design-system editors. Use Nuxt UI's [Theme Studio](https://ui.nuxt.com/theme) for advanced palette exploration; its internal document format is not this package's interchange format.
