title: Brand Studio
description: Create a reusable Nuxt UI brand, preview real applications and review changes before applying them.
---

[Open Studio](/studio?browse=true). The project menu opens, duplicates and restores brands. **Customize** opens the inspector. On mobile, settings use the available screen and **Preview** returns to the application.

## Add Studio

Studio is an optional authoring layer for a Nuxt UI application. Consumers of an exported brand receive native CSS, app config and assets; they do not need the id runtime or Docus.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@example/brand', '@happydesigns/id/studio']
})
```

```ts [app/app.config.ts]
import document from '../brand.studio.json'

export default defineAppConfig({
  idStudio: { document, sourcePath: 'brand.studio.json', home: '/' }
})
```

Use the import path to your actual source file.

## Preview real applications

Components and Landing are included. A capability can register its existing scenario as an async component, sharing code and fixtures with its own playground. Studio supplies `document`, `mode` and `page`; `navigate(pageId)` synchronizes the comparison frames.

Docs uses your host application's real Docus routes, Markdown, navigation and search. Add Docus to the authoring host and register a bounded route subtree:

```ts [app/app.config.ts]
export default defineAppConfig({
  idStudio: {
    templates: {
      docs: {
        label: 'Docs',
        owner: 'docus',
        route: '/docs/introduction',
        routePrefix: '/docs'
      }
    }
  }
})
```

This configuration is trusted application code. An imported brand cannot register routes or execute components. Frames stay on the same origin and within the configured subtree. One host server renders Studio and its previews. Selecting a template does not add that capability to the exported brand.

## Customize a draft

The inspector groups identity and logo variants, palette roles and stops, typography, and appearance. Primary and neutral colors are immediate controls; additional roles and existing component overrides are disclosed when needed. Logo uploads support PNG, JPEG and WebP up to 2 MB; existing local SVG references are preserved. Font stacks use fonts already available in the application and do not install fonts.

Compare shows the loaded or applied baseline beside the draft. Both use the same page and color mode, with independent interaction state. System, Light and Dark apply to the shell and preview together. View links contain only navigation, mode and comparison settings, never brand documents.

Unknown metadata, additional asset roles and component configuration survive editing. CSS classes still need to exist in the host's compiled styles; the preview cannot compile arbitrary classes from imported JSON. Contrast feedback measures body text against the page background, not every component or interaction state.

## Review and apply locally

A host can explicitly connect one absolute JSON path in private runtime configuration:

```ts [nuxt.config.ts]
import { fileURLToPath } from 'node:url'

export default defineNuxtConfig({
  extends: ['@happydesigns/id/studio'],
  runtimeConfig: {
    idStudioSource: fileURLToPath(new URL('./brand.studio.json', import.meta.url))
  }
})
```

Only the local development server registers this writer. **Changes** opens a field-level review. **Apply changes** validates and atomically replaces the connected JSON source after checking its revision. If another editor changed the file, Studio preserves the draft and refuses to overwrite it. Download the draft before reopening the connected project to resolve the conflict. New, imported and duplicated projects stay disconnected until explicitly reopened from the host.

The host owns regeneration of derived files. Exported projects include a generator and a source watch hook; an existing host should call its own generator when the source changes. Writing the JSON does not commit, publish or deploy anything.

## Download and recover

**Download source** provides the complete JSON. **Download new project** creates a native Nuxt UI layer with generated app config, CSS, BrandLogo and available public assets. Its optional development playground includes Studio and Docus. Custom Vue components, capability packages and font files must be added separately.

Install the exported project, then run `pnpm dev` or `pnpm build`. Run `pnpm generate:brand` after source changes outside the running playground. Generated files are derived output; edit the JSON source.

Until id is published, a host can set `idStudio.packageAsset` to a same-origin `.tgz` path. Studio includes that reviewed package as a development dependency and as a playground asset for subsequent exports. Without this option, substitute a reviewed local package for the registry dependency.

Drafts, comparison baselines and downloaded snapshots are stored under separate project IDs in this browser. Recent projects and recovery preserve work across switches and reloads. Browser storage is not a backup. If it fails, Studio asks before replacing unsaved work. Downloading does not advance the applied baseline; a successful local Apply does.

## Scope

Nuxt UI is the supported authoring target. Historical adapter helpers and runtime exports remain compatible APIs. `createStudioRuntimeFiles` generates native runtime files; `createStudioProject(document, { legacyRuntime: true })` retains the previous id-runtime project format for existing integrations.
