---
title: Nuxt UI Mapping
description: Map brand decisions to Nuxt UI semantic colors, CSS variables, and component defaults.
---

Nuxt UI is the primary rendering contract for `id`.

## Mapping order

1. Define raw brand palette values.
2. Map palette families to Nuxt UI semantic roles.
3. Set shared `--ui-*` CSS variables.
4. Configure component defaults in `app.config.ts`.
5. Use Nuxt UI components and semantic utilities in product markup.

## Semantic colors

```ts [brand.config.ts]
export const brandTheme = defineBrandTheme({
  name: 'client',
  label: 'Client',
  semanticColors: {
    primary: 'brand',
    secondary: 'teal',
    success: 'green',
    info: 'sky',
    warning: 'amber',
    error: 'red',
    neutral: 'slate'
  }
})
```

Nuxt UI uses these roles in component `color` props and semantic utilities.

## Component defaults

```ts [brand.config.ts]
export const brandTheme = defineBrandTheme({
  name: 'client',
  label: 'Client',
  ui: {
    button: {
      slots: {
        base: 'rounded-md font-medium'
      },
      defaultVariants: {
        color: 'primary',
        variant: 'solid',
        size: 'md'
      }
    },
    card: {
      slots: {
        root: 'rounded-md shadow-none'
      }
    }
  }
})
```

Stay close to Nuxt UI's theme object shape. Override stable slots, variants, compound variants, and default variants before introducing custom wrappers. Runtime themes should only use class names that are already shipped with the app.

## Product component rule

Reusable product components should prefer:

- `UButton`, `UCard`, `UFormField`, `UTable`, `UModal`, and other Nuxt UI primitives
- `color="primary"` or other semantic roles
- `text-default`, `text-muted`, `bg-default`, `bg-muted`, `border-default`
- standard color mode through `useColorMode()`

Avoid raw brand classes such as `text-blue-700` or `bg-[#123456]` in reusable product code.
