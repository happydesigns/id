---
title: Nuxt UI Mapping
description: Map brand decisions to Nuxt UI semantic colors, CSS variables, and component defaults.
---

Nuxt UI is the primary rendering contract for `id`.

## Mapping order

1. Define raw brand palette values.
2. Map named palette families to Nuxt UI semantic roles through `nuxtUiAdapter`.
3. Set shared `--ui-*` CSS variables.
4. Configure component defaults in `app.config.ts`.
5. Use Nuxt UI components and semantic utilities in product markup.

## Semantic colors

```ts [brand.ts]
import { defineBrand } from '@happydesigns/id'
import { nuxtUiAdapter } from '@happydesigns/id/adapters/nuxt-ui'

export const brand = defineBrand({
  name: 'client',
  colors: {
    coral: { 500: '#F28564' },
    petrol: { 500: '#2F6374' },
    sand: { 150: '#F1ECE6', 500: '#8F857A' }
  },
  roles: {
    signature: 'coral'
  }
})

export const brandTheme = nuxtUiAdapter.transform(brand, {
  label: 'Client',
  colors: {
    primary: brand.roles.signature,
    secondary: 'petrol',
    neutral: 'sand'
  }
})
```

Nuxt UI uses these roles in component `color` props and semantic utilities. Mapping is explicit because deciding which brand color is `primary` is a design decision. Omitted roles keep Nuxt UI defaults.

The mapping type offers the current well-known Nuxt UI role literals and also accepts custom strings. That open union is intentional: integrations can map a newly introduced or project-specific target role without waiting for an `id` release, while known roles still receive editor suggestions.

## Component defaults

```ts [brand.ts]
export const brandTheme = nuxtUiAdapter.transform(brand, {
  label: 'Client',
  colors: {
    primary: brand.roles.signature,
    neutral: 'sand'
  },
  components: {
    button: {
      slots: {
        base: 'rounded-md font-medium'
      },
      defaultVariants: {
        color: 'primary',
        variant: 'solid',
        size: 'md'
      }
    },
    card: {
      slots: {
        root: 'rounded-md shadow-none'
      }
    }
  }
})
```

Stay close to Nuxt UI's theme object shape. Override stable slots, variants, compound variants, and default variants before introducing custom wrappers. Runtime themes should only use class names that are already shipped with the app.

The adapter does not force color mode or synthesize dark values. Nuxt UI keeps its normal shade switching. Add `cssVariables.dark` only when the brand intentionally overrides particular dark-mode tokens.

## Product component rule

Reusable product components should prefer:

- `UButton`, `UCard`, `UFormField`, `UTable`, `UModal`, and other Nuxt UI primitives
- `color="primary"` or other semantic roles
- `text-default`, `text-muted`, `bg-default`, `bg-muted`, `border-default`
- standard color mode through `useColorMode()`

Avoid raw brand classes such as `text-blue-700` or `bg-[#123456]` in reusable product code.
