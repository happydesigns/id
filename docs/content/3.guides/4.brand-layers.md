---
title: Brand Layers
description: Build full Nuxt brand layers with @happydesigns/id contracts and Nuxt UI defaults.
---

A brand layer is the right shape when branding owns more than runtime-safe values.

## Minimal layer

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@happydesigns/id/nuxt'],
  css: ['~/assets/css/brand.css'],
  app: {
    head: {
      link: [
        { rel: 'icon', type: 'image/svg+xml', href: '/favicon.svg' }
      ]
    }
  }
})
```

## App config

```ts [app.config.ts]
import { brandGuide, brandTheme } from '../brand.config'

export default defineAppConfig({
  id: {
    defaultTheme: brandTheme.name,
    themes: [brandTheme],
    guide: brandGuide
  },
  ui: {
    colors: brandTheme.semanticColors
  }
})
```

## Layer ownership

Brand layers can provide:

- public assets
- metadata
- CSS token definitions
- Nuxt UI defaults
- logo components
- app shell wrappers
- docs styling

They should not provide product permissions, storage behavior, API contracts, or workflow rules.

## Multi-brand deployments

For deploy-time brand selection, keep the app brand-neutral and select the layer in `nuxt.config.ts`.

```ts [nuxt.config.ts]
const brandLayer = process.env.NUXT_BRAND_LAYER ?? '@client/default-brand'

export default defineNuxtConfig({
  extends: [brandLayer]
})
```

This keeps one app source while allowing deployment-specific brand expression.
