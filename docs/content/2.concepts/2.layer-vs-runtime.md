---
title: Layer vs Runtime
description: Choose between build-time Nuxt brand layers and runtime theme packs.
---

Build-time layers and runtime themes solve different branding jobs.

## Comparison

| Capability | Brand layer | Runtime theme pack |
| --- | --- | --- |
| CSS variables | Yes | Yes |
| Nuxt UI semantic colors | Yes | Yes |
| Component defaults | Yes | Yes, when classes are already compiled |
| Logos and public assets | Yes | Only if already shipped |
| Layout wrappers | Yes | No |
| Custom Vue components | Yes | Only if already bundled |
| App metadata | Yes | Limited |
| Domain behavior | No | No |

## Recommended default

Use brand layers for customer or product deployments. They are explicit, cacheable, reviewable, and work with Nuxt's normal layer priority model.

Add runtime theme packs when users need a theme picker, preview mode, tenant preview, or editor workflow that changes visual tokens without rebuilding the app.

## Avoid false runtime promises

Runtime branding is fast because it is limited. It should not pretend to swap arbitrary component libraries, route files, public assets, or Tailwind classes that were not present at build time.
