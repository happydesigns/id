`id` separates the identity contract from concrete brand expression.

## Core objects

| Object | Purpose |
| --- | --- |
| Brand guide | Durable identity source: metadata, assets, tokens, voice, component coverage, and usage rules. |
| Brand theme | Runtime-safe subset: semantic colors, CSS variables, typography variables, and Nuxt UI defaults. |
| Brand layer | Nuxt layer that applies a concrete brand at build time. |
| Themed app | Nuxt app that consumes one or more theme packs without a separate brand-layer package. |

## Token flow

```mermaid
flowchart LR
  Guide["Brand guide"] --> Palette["Raw palette"]
  Palette --> Roles["Nuxt UI semantic roles"]
  Roles --> Variables["CSS variables"]
  Variables --> Defaults["app.config.ts defaults"]
  Defaults --> Components["Nuxt UI components"]
```

The application should consume semantic roles and variables. The brand guide explains why those values exist.

## Why this matters

The same product can receive different identity expression when product components stay brand-neutral. Components ask for role-based values. Brand layers and theme packs provide those values.
