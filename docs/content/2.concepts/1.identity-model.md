title: Identity Model
description: Brand source, Nuxt UI configuration and reusable native layers.

ID complements Nuxt UI with brand authoring and application previews. Applications use Nuxt UI components and semantic roles; a shared brand layer supplies their appearance. ID does not introduce a second component system or a framework-neutral theme standard.

## Core objects

| Object | Purpose |
| --- | --- |
| Brand source | A versioned Studio document containing named colors, typography, assets and the theme configuration. |
| Theme configuration | Nuxt UI component defaults and semantic color mappings, plus brand CSS variables for light and dark mode. |
| Brand layer | Generated native Nuxt configuration and CSS, adopted deliberately by consuming applications. |
| Application preview | A development integration that applies a temporary draft to an application's own routes and components. |
| Brand guide | Optional editorial context and technical references, separate from application runtime requirements. |

## From source to applications

Edit the brand source in Studio, check it in your applications, and generate its native layer. Consuming applications update the brand dependency and rebuild. Their features, routes and content remain theirs; they do not need ID at runtime.

Brand colors retain their names. Nuxt UI semantic roles map to those palettes, while component defaults use Nuxt UI's configuration. Omitted settings retain upstream defaults. Additional light/dark CSS variables describe brand-specific overrides, not a replacement color-mode implementation.

The editable source also retains assets and optional authoring information that component configuration alone does not describe. Native generation emits only the files needed by the brand layer.

## Relationship to Nuxt UI

Use public upstream capabilities wherever they cover the workflow. The current editor, preview resets and example gallery fill integration gaps; they are replaceable implementations, not permanent competing APIs. ID may become smaller as Nuxt UI gains reusable authoring and preview capabilities.

## Existing integrations

The published brand adapters, identity runtime and runtime theme selection remain supported for existing applications. New projects follow the native layer workflow. Their compatibility APIs do not imply a roadmap for additional UI frameworks. See [Layer and runtime model](/concepts/layer-vs-runtime) for the distinction.
