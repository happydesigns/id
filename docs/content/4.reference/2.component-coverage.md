---
title: Component Coverage
description: Audit Nuxt UI component families when validating a brand guide.
---

A brand guide should prove how identity behaves across real Nuxt UI surfaces.

## Families

| Family | Components to check | Why it matters |
| --- | --- | --- |
| Actions | `UButton`, `UBadge`, `UDropdownMenu`, `UTooltip` | Hierarchy, focus, hover, destructive treatment. |
| Forms | `UForm`, `UFormField`, `UInput`, `UTextarea`, `USelect`, `UCheckbox`, `USwitch` | Labels, help text, focus rings, validation states. |
| Feedback | `UAlert`, `UToast`, `UProgress`, `UEmpty`, `USkeleton` | Status colors, contrast, calm recovery messaging. |
| Navigation | `UHeader`, `UNavigationMenu`, `UBreadcrumb`, `UTabs`, `UStepper` | Wayfinding, active states, density. |
| Data | `UTable`, `UCard`, `UAvatar`, `USeparator`, `UTimeline` | Dense surfaces, borders, zebra states, metadata. |
| Overlays | `UModal`, `USlideover`, `UDrawer`, `UPopover` | Depth, backdrop, destructive flows. |
| Docs prose | Markdown prose, code blocks, callouts, cards, tabs | Brand guide readability and developer trust. |
| App shell | Dashboard, sidebars, page layouts, headers, footers | Repeated product work surfaces. |

## Status levels

| Status | Meaning |
| --- | --- |
| `planned` | The family is identified but not styled or documented. |
| `tokenized` | The family uses shared tokens and Nuxt UI defaults. |
| `documented` | The family has visible usage guidance. |
| `verified` | The family passed visual QA across light, dark, desktop, and mobile. |

Use `IdComponentCoverageTable` when a brand guide wants to render the current `id.guide.componentCoverage` entries without hand-maintaining a Markdown table.

```mdc [coverage.md]
::id-component-coverage-table
::
```

Use `caption` when the page needs a more specific accessible table name. The caption is visually hidden by default.

If a brand layer extends another layer that already defines `id.guide.componentCoverage`, pass explicit `items` from the brand-owned source file. Nuxt app-config merging can concatenate arrays from extended layers.

When the table reads from `app.config.ts`, use Nuxt's `defuFn` replacement hook for that array:

```ts [app.config.ts]
const appConfigGuide = {
  ...brandGuide,
  componentCoverage: () => brandComponentCoverage
}

export default defineAppConfig({
  id: {
    guide: appConfigGuide
  }
})
```

## Minimum release bar

Before publishing a brand layer, verify actions, forms, feedback, navigation, data tables, overlays, and docs prose in both light and dark mode. These surfaces reveal most token mistakes.

Use `IdComponentExample` for the default Nuxt UI examples that support this review. The examples are grouped by family in the public `componentExampleGroups` export, so a brand can list coverage metadata from source and render the same example names in docs.
