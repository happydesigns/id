## TypeScript helpers

| Export | Purpose |
| --- | --- |
| `defineBrandGuide` | Validate and return a typed brand guide. |
| `defineBrandTheme` | Validate and return a typed brand theme. |
| `validateBrandGuide` | Validate unknown input and return a `BrandGuide`. |
| `validateBrandTheme` | Validate unknown input and return a `BrandTheme`. |
| `createThemeCssVars` | Render light and dark CSS variable blocks. |
| `createThemeCssDeclarations` | Render declarations for one mode. |
| `createNuxtUiAppConfig` | Convert a theme to Nuxt UI app config. |
| `collectBrandAssets` | Flatten `id.guide.assets.logos` and `assets.files` into selectable entries. |
| `selectBrandAsset` | Select an asset by role, media, and fallback roles. |
| `normalizeBrandThemes` | Collapse Nuxt app-config merged theme arrays by unique theme name. |
| `resolveBrandThemes` | Return `id.theme` first, followed by optional unique `id.themes[]` entries. |
| `parseDocsLinks` | Parse docs-link strings or typed link arrays for reusable guide components. |
| `applyBrandTheme` | Apply CSS variables and optionally update app config. |
| `nuxtUiBrandTheme` | Default Nuxt UI baseline theme shipped by `id`. |
| `idBrandGuide` | Default identity guide for the shipped `id` baseline. |

## Theme exports

```ts [theme-imports.ts]
import { nuxtUiBrandTheme } from '@happydesigns/id/themes/nuxt-ui'
import { happydesignsBrandTheme } from '@happydesigns/id/themes/happydesigns'
```

The root package re-exports the Nuxt UI baseline for convenience. The theme subpaths make it clear whether a project is using the standard baseline or the local happydesigns demonstration theme. That local theme exists to show the `id` contract; `@happydesigns/brand` owns the final happydesigns guide and assets.

## Layer export

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@happydesigns/id/nuxt']
})
```

The package export points to the public identity layer. It registers Nuxt UI, the `Id` runtime components, and identity CSS. It does not include repository-only tooling such as `@nuxt/eslint`.

Layer components are prefixed with `Id`. `IdNuxtUiDocsLink` renders compact links to Nuxt UI documentation and accepts either typed links or an MDC-friendly string:

```mdc [component-docs.md]
::id-nuxt-ui-docs-link{links="UButton|https://ui.nuxt.com/docs/components/button; UTooltip|https://ui.nuxt.com/docs/components/tooltip"}
::
```

`IdExampleFrame` provides a neutral surface for visible brand-guide examples:

```mdc [component-docs.md]
::id-example-frame
  <!-- Brand-owned example content stays here. -->
::
```

Use `variant="plain"` when the example already owns its own frame or layout surface.

## Module export

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@happydesigns/id/module'],
  id: {
    name: 'client',
    componentPrefix: 'Id'
  }
})
```

The layer export uses the `Id` component prefix. The module can use another global prefix when a host app needs to avoid naming collisions.

## App config

```ts [app.config.ts]
export default defineAppConfig({
  id: {
    name: 'client',
    theme: clientTheme,
    guide: brandGuide
  }
})
```

Use `id.name` and `id.theme` for normal brand layers. Use `id.themes[]` and `id.defaultTheme` only for apps that intentionally ship multiple runtime-selectable themes.

## Brand assets

`id.guide.assets.logos` is a typed `Record<string, BrandAsset>`. Known role names such as `logo`, `wordmark`, `symbol`, `mark`, and `appIcon` are conveniences only. Brand layers may define any role name that matches their identity system.

`IdLogo` reads that map and can render a specific role:

```vue [BrandLogo.vue]
<IdLogo role="crest" />
```

Without a role, it renders the first common logo role it can find, then falls back to the first configured asset, then to the brand title.

For custom components, use the same asset selection logic through `useBrandAssets()` or the framework-neutral helpers:

```ts [brand-assets.ts]
import { collectBrandAssets, selectBrandAsset } from '@happydesigns/id'

const asset = selectBrandAsset(collectBrandAssets(brandGuide), {
  role: 'signature',
  media: 'dark'
})
```

## Validation error

Invalid contracts throw `BrandValidationError` with an `issues` array. Use that list in CLI or editor workflows to show actionable errors.
