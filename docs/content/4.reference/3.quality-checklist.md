---
title: Quality Checklist
description: Review a brand guide, runtime theme, and Nuxt layer before publishing.
---

Use this checklist before releasing a brand guide or layer.

## Contract

- The raw brand source validates with `defineBrandIdentity`.
- The brand guide validates with `defineBrandGuide`.
- Every theme validates with `defineBrandTheme`.
- Theme names are stable kebab-case identifiers.
- Usage limits are documented.
- Runtime limits are explicit.

## Nuxt UI

- Semantic colors map to real Tailwind color families.
- Shared component defaults live in `app.config.ts`.
- Product components use semantic utilities instead of raw brand colors.
- Dense components such as tables and forms are checked.
- Dark mode variables are provided or intentionally unsupported.

## Layer

- Logos and public assets have clear roles.
- Favicons and metadata are set in the layer.
- Custom components are brand primitives, not product behavior.
- The layer can be removed without breaking domain logic.

## Runtime

- Theme packs only contain serializable public data.
- Runtime switching uses shipped variables and classes.
- No credentials, private endpoints, or scripts are stored in theme data.
- The default theme renders correctly on first SSR response.

## Docs

- The landing page explains the brand model.
- Getting started reaches a working example quickly.
- API docs match source behavior.
- Component coverage shows what is verified.
- Boundaries are clear enough for future contributors.
