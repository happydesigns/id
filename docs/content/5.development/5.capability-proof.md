---
title: Real application proof
description: Verify one company brand against the maintained Course and Booking playgrounds.
---

This opt-in local integration checks the same applications their capability owners maintain. It does not copy their routes into ID or publish a customer brand. The initial proof uses Course, Booking and Erste-Hilfe-Schule Rhein-Main; customer sources remain unchanged.

## Prepare

Build ID with `pnpm build:package`. With the three selected checkouts installed, run:

```sh
node --experimental-strip-types tests/helpers/prepare-capability-proof.mjs BRAND_ROOT COURSE_ROOT BOOKING_ROOT
```

This helper reads the selected brand's `brand.ts`, `theme.ts`, public assets and supplementary stylesheet. It writes generated layers and CSS entries only below `.output/capability-proof`. The stylesheet imports each playground's existing entry, the brand's supporting CSS, then the newly generated brand fragment. Assets and local font files are copied explicitly; a theme JSON alone does not contain them. This is a fixture for the selected brand structure, not another public project generator.

## Preview builds

For each existing playground, set these environment variables before its normal build:

| Variable | Value |
| --- | --- |
| `ID_PREVIEW_MODULE` | Absolute path to ID's `dist/preview-module.js`. |
| `ID_STUDIO_ORIGIN` | `http://127.0.0.1:3439` |
| `ID_PREVIEW_BUILD` | `1` |
| `ID_BRAND_LAYER` | Absolute path to `.output/capability-proof/original`. |
| `ID_BRAND_UI` | Absolute path to `.output/capability-proof/brand-ui.json`. |
| `ID_BRAND_CSS` | Absolute path to `original-course.css` or `original-booking.css` in the proof directory. |

Serve the resulting Course and Booking servers on ports 3461 and 3462. Build the existing ID guide fixture with `ID_CAPABILITY_DOCUMENT` pointing to `.output/capability-proof/brand.json`, then serve it on 3439 through `tests/helpers/serve-static.mjs` (`PORT=3439`). Run:

```sh
pnpm exec playwright test --config playwright.capabilities.config.ts
```

The browser changes the radius through the existing Studio editor, checks preserved course progress and booking input, exports the edited brand and exercises both apps at 390 and 1100 pixels in light and dark mode. Screenshots and computed appearance measurements stay in the ignored proof directory. Booking uses local demonstration data; this proves no external reservation or payment.

## Native comparison

Pass the browser-exported `.output/capability-proof/exported-booking.json` as the fourth argument to the same preparation command. This generates the edited native layer. Stop the preview servers. Rebuild each playground with only `ID_BRAND_LAYER` pointing to `edited` and `ID_BRAND_CSS` pointing to its `edited-*.css` entry. Unset the preview variables. Restart the built servers on the same ports and run the suite with `ID_CAPABILITY_NATIVE=1`.

The native checks compare computed brand appearance with the preview and exercise the actual application controls again. Inspect the built client for the preview protocol marker and configuration to ensure the bridge was excluded. The consuming apps keep their own dependencies, authentication and delivery process.

## Measurements and limits

The native suite records browser-observed load-plus-interaction time, resource count and transferred bytes for each mode and width. These local sequential samples include browser automation, font loading and cache effects. They are diagnostic evidence, not a production performance benchmark or a comparison with ui.nuxt.com. Memory and cold/warm latency distributions still require a controlled benchmark before an upstream performance claim.

The code uses public Nuxt module, layer and DevTools integration APIs. A future upstream proposal should focus on a reusable controlled editor, theme application/restoration and an explicit app-preview bridge. Nuxt core app isolation is a separate discussion. The [product vision](/concepts/product-vision) remains the proposal outline; no issue or contribution is posted automatically.
