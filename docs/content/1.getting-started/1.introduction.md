title: Introduction
description: Develop Nuxt UI applications independently of their brand identity.
---

ID helps you create a shared brand without coupling application features to it. Build applications with Nuxt UI components, semantic colors and stable asset roles. Edit the brand in Studio, verify it in your applications and generate a native Nuxt layer.

Applications consume that layer and its CSS. They do not need ID, Studio or Docus at runtime. Each application adopts a new brand version through its normal build and delivery process.

## The native workflow

1. [Create a brand](/guides/starters) in Studio or connect an existing source.
2. [Preview your applications](/guides/brand-studio#preview-a-separately-running-app) while editing.
3. Export or regenerate the native brand layer.
4. [Apply the brand](/getting-started/apply-branding) to each application.
5. Review changes, update the shared package and rebuild consumers.

Studio owns authoring, not the application's features. A documentation site is optional; add the Guide/Docus integration when a brand needs a reference portal.

## Keep applications brand-ready

- Use Nuxt UI components and semantic utilities such as `text-default`, `bg-muted` and `border-default`.
- Keep application-specific UI defaults in `app.config.ts`.
- Consume logos through stable asset roles.
- Ship the required fonts, assets and custom components.
- Keep domain behavior and permissions outside branding.

ID does not infer artistic direction or automatically restyle hardcoded colors and third-party widgets.

## Existing runtime integrations

The identity runtime and `id.theme` remain supported for existing consumers and applications that intentionally switch shipped themes at runtime. They are optional compatibility integrations, not prerequisites for native brands. See [Installation](/getting-started/installation) and [Runtime themes](/guides/runtime-themes).
