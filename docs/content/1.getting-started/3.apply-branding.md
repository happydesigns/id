---
title: Apply Branding
description: Decide whether a Nuxt project should use a brand layer, optional runtime theme list, or product-level change.
---

Branding should be applied at the level that owns the change.

## Full brand layer

Use a Nuxt brand layer when the identity owns files, assets, composition, or app shell behavior.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@client/brand']
})
```

A brand layer can own:

- palettes and CSS variables
- Nuxt UI semantic mappings
- `app.config.ts` component defaults
- logos, favicons, app icons, and public assets
- metadata and head defaults
- layouts and app shell wrappers
- brand primitives
- docs styling

For deployment-specific branding, keep the product app neutral and select the layer through environment-controlled config.

```ts [nuxt.config.ts]
const brandLayer = process.env.NUXT_BRAND_LAYER ?? '@client/brand'

export default defineNuxtConfig({
  extends: [brandLayer]
})
```

For local preview or CI, download a brand layer into the app without committing product changes.

```bash [Terminal]
npx giget github:client/brand layers/90.brand
pnpm dev
```

## Optional runtime themes

Use runtime themes when the app only needs to switch shipped values. `useBrandTheme()` reads the primary `id.theme` from app config and any optional `id.themes[]` entries supplied by the active layers.

```vue [ThemeSwitcher.vue]
<script setup lang="ts">
const { themes, currentName, setTheme } = useBrandTheme()
</script>

<template>
  <USelect
    :items="themes.map(theme => ({ label: theme.label, value: theme.name }))"
    :model-value="currentName"
    value-key="value"
    label-key="label"
    @update:model-value="value => typeof value === 'string' && setTheme(value)"
  />
</template>
```

Runtime themes can change CSS variables, typography variables, Nuxt UI `ui.colors`, and app-config defaults.

## Product app change

Use the product app when the change affects behavior.

Branding must not own:

- permissions
- tenant isolation
- API behavior
- data validation
- storage
- billing rules
- audit behavior
- credentials

Those decisions belong to the product that owns the workflow.
