Install the package in a Nuxt app or in a brand-layer repository.

::code-group
```bash [pnpm]
pnpm add @happydesigns/id
```

```bash [npm]
npm install @happydesigns/id
```

```bash [yarn]
yarn add @happydesigns/id
```

```bash [bun]
bun add @happydesigns/id
```
::

## Extend the base layer

Brand repositories normally extend the reusable `id` Nuxt layer, then add their own assets, CSS, app shell pieces, and `app.config.ts`.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@happydesigns/id/nuxt']
})
```

## Use the module

Use the module when the project wants explicit module options instead of extending the base layer.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@happydesigns/id/module'],
  id: {
    name: 'client'
  }
})
```

## Configure the brand

Expose the primary brand theme through `app.config.ts`. This mirrors Nuxt UI's own configuration model: public, serializable defaults live in app config; files, assets, layouts, and server behavior stay in the Nuxt layer or product app.

```ts [app.config.ts]
import { createNuxtUiAppConfig, defineBrandTheme } from '@happydesigns/id'

const clientTheme = defineBrandTheme({
  name: 'client',
  label: 'Client',
  cssVariables: {
    light: {
      '--ui-bg': 'white',
      '--ui-text': '#334155',
      '--ui-text-highlighted': '#020617'
    }
  },
  ui: {
    colors: {
      primary: 'blue',
      neutral: 'slate'
    }
  }
})

const nuxtUiConfig = createNuxtUiAppConfig(clientTheme)

export default defineAppConfig({
  id: {
    name: clientTheme.name,
    theme: clientTheme
  },
  ui: nuxtUiConfig.ui
})
```

## Apply a brand layer

A brand-neutral app can consume a brand layer directly, without changing product code.

```ts [nuxt.config.ts]
const brandLayer = process.env.NUXT_BRAND_LAYER ?? '@client/brand'

export default defineNuxtConfig({
  extends: [brandLayer]
})
```
