Install the package in a Nuxt app or in a brand-layer repository.

::code-group
```bash [pnpm]
pnpm add @happydesigns/id
```

```bash [npm]
npm install @happydesigns/id
```

```bash [yarn]
yarn add @happydesigns/id
```

```bash [bun]
bun add @happydesigns/id
```
::

## Extend the base layer

Brand repositories normally extend the reusable `id` Nuxt layer, then add their own assets, CSS, app shell pieces, and `app.config.ts`.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@happydesigns/id/nuxt']
})
```

## Use the module

Use the module when the project wants explicit module options instead of extending the base layer.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@happydesigns/id/module'],
  id: {
    name: 'client',
    componentPrefix: 'Id'
  }
})
```

`Id` is the default global component prefix. Keep it unless your app already owns component names such as `IdLogo`, `IdThemeSelect`, or `IdColorModeButton`.

## Configure the brand

Expose the primary brand theme through `app.config.ts`. This mirrors Nuxt UI's own configuration model: public, serializable defaults live in app config; files, assets, layouts, and server behavior stay in the Nuxt layer or product app.

For reusable brand repositories, keep the actual brand source in a normal file such as `brand.ts`, then import it from `app.config.ts`. That keeps the brand testable and exportable while still using Nuxt's standard app-config model.

```ts [app.config.ts]
import { createNuxtUiAppConfig, defineBrandTheme } from '@happydesigns/id'

const clientTheme = defineBrandTheme({
  name: 'client',
  label: 'Client',
  cssVariables: {
    light: {
      '--ui-bg': 'white',
      '--ui-text': '#334155',
      '--ui-text-highlighted': '#020617'
    }
  },
  ui: {
    colors: {
      primary: 'blue',
      neutral: 'slate'
    }
  }
})

const nuxtUiConfig = createNuxtUiAppConfig(clientTheme)

export default defineAppConfig({
  id: {
    name: clientTheme.name,
    theme: clientTheme
  },
  ui: nuxtUiConfig.ui
})
```

The default Nuxt UI baseline can be imported from `@happydesigns/id/themes/nuxt-ui`. The local happydesigns demonstration theme used by these docs lives at `@happydesigns/id/themes/happydesigns`. Treat that local theme as an example of the integration shape; `@happydesigns/brand` owns the final happydesigns brand source.

## Apply a brand layer

A brand-neutral app can consume a brand layer directly, without changing product code.

```ts [nuxt.config.ts]
const brandLayer = process.env.NUXT_BRAND_LAYER ?? '@client/brand'

export default defineNuxtConfig({
  extends: [brandLayer]
})
```

The consuming app should still set its own `compatibilityDate` in `nuxt.config.ts`. The `id` layer has a compatibility date for its own development and starter projects, but an app-level value is the deployment contract for the product that extends it.
